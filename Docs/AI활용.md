# AI를 도구로 활용한 방식 (기획서용 초안)

> 기획서의 "AI 활용" 파트에 옮겨 쓰기 위한 정리입니다.
> 사실만 적고, 근거(커밋 기록, 구현노트)를 함께 남깁니다. 작업이 진행되면 계속 업데이트합니다.

## 핵심 메시지
**AI에게 게임을 "맡긴" 것이 아니라, 기획·판단·검증은 내가 하고 AI는 구현을 빠르게 하는 도구로 사용했다.**

## 1. 역할 분담 원칙
| 단계 | 내가 한 일 | AI가 한 일 |
|---|---|---|
| 기획 | 게임 컨셉 선택, 나만의 기능 아이디어, 조작 방식 결정 | 선택지 제시, 장단점 비교 |
| 구현 | 쉬운 기능 직접 작성, 방향 지시, 수치 조정 | 복잡한 기능 코드 작성, 원리 설명 |
| 검증 | Unity에서 직접 플레이 테스트, 문제 발견 | 발견한 문제의 원인 분석, 수정 |
| 기록 | 진행 관리, 최종 판단 | 구현노트 정리 |

## 2. 내가 내린 결정들 (AI의 제안을 그대로 쓰지 않은 사례)
| 상황 | AI 제안 | 나의 결정 |
|---|---|---|
| 게임 컨셉 | 기획안 4개 제시 | 웨이브 서바이벌 선택 + 시간이 남으면 보스(③) 요소를 섞는 방식으로 결정 |
| 나만의 기능 | 업그레이드 상점 | **정밀 조준(우클릭 스코프)** 을 직접 제안 |
| 추가 기능 | - | **지도 포격**(배틀그라운드식 M키 지도)을 직접 제안, 3~5연발로 수정 |
| 지도 포격 사거리 한계 | 사거리 밖 안내 | "포신 각도 제한을 넓히면 되지 않나?" 질문 → 각도 확장 + 속도 조절로 해결 |
| 조준 방식 | 휠로 포신 조절 유지 | **휠을 없애고 조준점 하나로 통합**하자고 제안 |
| 정밀 조준 밸런스 | 항상 자동 탄도 계산 | "그러면 정밀 조준 의미가 없고 너무 사기다"라고 판단 → **일반=직사 / 정밀=탄도 보정(A안)** 으로 결정 |
| 아군 AI | - | 아이디어 제시 후, 마감 일정을 보고 **필수 요구사항 우선**으로 순서 조정 |
| 배경 테마 | 사막 (기획안 ①) | 다른 학생들과 겹치지 않게 **설원으로 변경** |
| URP 전용 폭발 에셋 | 프로젝트 전체 URP 변환 / 교수님 팩 / 머티리얼만 변환 | 다른 에셋이 깨질 위험을 보고 **머티리얼만 변환**하는 방법 선택 |
| 맵 언덕 | 언덕 추가 방법 안내 | 직접 그려 보고 너무 울퉁불퉁해서 **되돌리기로 결정** |
| 지도 포격 조작 | 클릭으로 목표 지정 | **휠 확대·축소, 끌어서 이동**(배그식) 추가 제안 |
| HUD 배치 | 자동 배치 도구 | 배치 결과를 보고 **위치·크기·색을 직접 다듬어** 최종 디자인 |
| 기지 구조물 | 자동 배치 | 설원에서 튀지 않도록 **흰색 계열**로 맞추자는 방향 결정 |
| 채점 편의 | - | **보스전 바로가기** 버튼 아이디어 (교수님이 보스까지 5웨이브를 다 깨지 않아도 되도록) |
| 개발 범위 | 기능 추가 계속 가능 | 화려한 기능보다 **완성도와 직접/AI 구분을 명확히** 하는 쪽이 과제 의도에 맞다고 판단해 기능 추가를 마무리 |

## 3. 직접 테스트하며 발견한 문제
| 문제 | 발견 | 해결 |
|---|---|---|
| 카메라가 차체만 따라가서 조준이 어려움 | 직접 플레이하며 발견, "포신 따라 카메라가 움직이게" 방향 제시 | 마우스 시점 카메라 + 화면 중앙 조준 |
| 적 일부가 나타나지 않아 웨이브 진행 안 됨 | 직접 발견 | 소환 위치 검사(경사·높이), 뒤집힘 복구 |
| 2~3웨이브에서 계속 패배 (난이도 과다) | 직접 발견 | HP·회복·적 수치 조정, Inspector 배율 추가 |
| 임포트한 폭발 이펙트가 분홍색 | 직접 발견 | 원인(URP 전용 셰이더) 분석 후 머티리얼 변환 |
| 파괴 폭발이 안 나옴 | 직접 작성한 코드에서 발견 | `Resources.Load` 이름 불일치를 직접 수정 |
| 아이템 작업 중 Resources 폴더가 사라짐 | 직접 발견 | Git으로 마지막 커밋 상태 복구 |
| 지도를 열면 화면용 적 표시가 겹쳐 헷갈림 | 직접 발견 | 지도가 열려 있을 때 화면 표시 숨김 |
| 재장전바 양옆 여백 | 직접 발견 | 여백 값 직접 조정 |
| 바닥이 너무 하얘서 지형이 안 보임 | 직접 발견 | 조명·주변광·안개·텍스처 직접 조정 |
| 과제 요구사항 중 "건물"이 빠짐 | 안내문과 비교해 직접 발견 | 군사 기지 구조물 추가 |
| 건물이 땅에 묻히거나 떠 보임 | 직접 발견 | 건물 밑 지형 평탄화 |
| **전차가 건물을 뚫고 지나가며 하늘로 튐**, AI가 건물을 피하는지 의문 | 직접 발견·질문 | 원인(수업 코드의 순간이동식 이동) 분석 → 물리 기반 이동, AI 장애물 회피 |

## 4. 직접 작성한 코드
- **포신 각도 제한** (`CannonCtrl`): 변수로 각도 저장 → `Mathf.Clamp` → `Quaternion.Euler`로 대입 (AI는 힌트와 리뷰만)
  - 이후 조준 방식을 바꿀 때도 이 구조를 그대로 유지
- **AI가 제시한 구조를 바탕으로 직접 입력·적용한 코드**: 아이템(`Item`, `ItemDropper`), 씬 전환(`SceneLoader`), 파괴 폭발(`TankHealth.Die`), 아이템 둥실둥실 움직임
  - 입력하면서 생긴 문제(폭발 프리팹 이름 불일치)는 직접 찾아 수정
- **코드 외 직접 작업**: 씬과 UI 구성(Intro·승리·패배 버튼 연결, HUD 오브젝트 생성과 최종 디자인), 아이템 프리팹·빛나는 머티리얼, 폭발 이펙트 연결과 큰 폭발 제작, 설원 지형·조명·안개·눈 효과, 에셋 선택·임포트, 밸런스 판단

## 5. 작업 관리 방식
- **Git/GitHub으로 버전 관리**: 기능 단위로 커밋해서 진행 과정을 기록 (2026-10-07 시작)
- **구현노트(`Docs/구현노트.md`)**: 기능마다 구현 방법, 핵심 코드, 직접/AI 구분을 기록
- **기획 문서(`Docs/기획.md`)**: 기획 변경 사항을 계속 반영
- AI가 만든 코드는 바로 쓰지 않고 **Unity에서 직접 실행해 확인한 뒤** 커밋

## 6. AI가 틀렸을 때
- `TankCamera`에서 `SmoothFollow` 네임스페이스를 빠뜨려 컴파일 에러 → 에러를 확인해서 알려 주고 수정
- 문서를 고치는 셸 명령에서 따옴표 처리를 잘못해 문서 일부 글자가 빠지고 빈 파일이 생김 → 확인 후 바로 복구하고 정리 커밋
- 구현노트에 **실제로 하지 않은 작업**(바위 텍스처 칠하기)을 한 것처럼 적음 → 커밋 전 바뀐 파일을 확인해서 사실과 다른 줄을 바로 삭제
- → AI 결과물은 그대로 믿지 않고 **실행 결과와 실제 변경 내역으로 확인**하는 습관이 필요함
