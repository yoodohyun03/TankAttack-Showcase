## 1. 포신 각도 제한

- **요구사항**: 2-2 플레이어 탱크 기능 추가 (포신 각도 조절 제한)
- **스크립트**: `Assets/02.Scripts/CannonCtrl.cs`
- **상태**: ✅ 완료

### 문제
수업 버전은 휠 입력만큼 `tr.Rotate(angle, 0, 0)`으로 회전을 계속 더하기만 해서, 포신이 위아래로 끝없이 돌아 차체와 땅을 뚫고 한 바퀴를 돌았다.

### 구현 방법
1. 포신의 현재 각도를 변수 `currAngle`에 직접 저장한다.
2. 휠 입력만큼 `currAngle`에 더한다.
3. `Mathf.Clamp`로 `minAngle ~ maxAngle` 범위를 넘지 않게 자른다.
4. 자른 각도를 `localRotation`에 **덮어쓴다** (`Rotate`처럼 누적하지 않음).

```csharp
float currAngle = 0.0f;
public float minAngle = -20.0f;   // 위쪽 한계 (Unity X축 회전은 음수가 위쪽)
public float maxAngle = 20.0f;    // 아래쪽 한계

void Update()
{
    float angle = -Input.GetAxis("Mouse ScrollWheel") * Time.deltaTime * rotSpeed;
    currAngle += angle;
    currAngle = Mathf.Clamp(currAngle, minAngle, maxAngle);
    tr.localRotation = Quaternion.Euler(currAngle, 0.0f, 0.0f);
}
```

### 포인트
- `transform.localEulerAngles.x`를 읽어서 쓰면 -10°가 350°로 나와 Clamp가 깨지므로, 각도를 직접 변수로 관리했다.
- `localRotation`은 `Quaternion` 타입이라 `Quaternion.Euler()`로 변환해서 대입했다.
- `minAngle`, `maxAngle`을 `public`으로 열어 Inspector에서 조절할 수 있게 했다.

### 직접 / AI 구분
- **직접**: `CannonCtrl.cs` 코드 작성, 각도 범위 설정과 테스트
- **AI 도움**: 구현 방향 힌트(변수 저장 → Clamp → 덮어쓰기), `Vector3`를 `localRotation`에 넣어 생긴 타입 오류 원인 설명, Clamp 반환값 미사용과 실행 순서 문제 지적, 최종 코드 리뷰

## 2. HP · 데미지 시스템

- **요구사항**: 적 AI, 아이템(HP 회복), 승리·패배 판정의 기반
- **스크립트**: `TankHealth.cs` (신규), `Cannon.cs`, `FireCannon.cs` (수정)
- **상태**: ✅ 완료 (큐브 표적으로 피격·파괴 확인)

### 구현 방법
1. `TankHealth` 컴포넌트를 플레이어와 적 탱크에 공통으로 붙인다.
   - `maxHp`, `currHp`, `TakeDamage()`, `Heal()`, `Die()`
   - 체력은 `Mathf.Clamp`로 0 ~ maxHp 범위 유지
   - `OnHpChanged`, `OnDeath` 이벤트를 두어 HP바 UI와 게임 매니저(패배 처리)가 나중에 구독할 수 있게 함
2. 포탄(`Cannon`)이 `OnTriggerEnter`에서 맞은 대상의 `TankHealth`를 찾아 `TakeDamage(damage)` 호출
   - 콜라이더가 탱크의 자식에 있을 수 있어 `GetComponentInParent<TankHealth>()` 사용, 지형에 맞으면 null이라 무시

```csharp
TankHealth health = other.GetComponentInParent<TankHealth>();
if (health != null)
{
    health.TakeDamage(damage);
}
```

### 해결한 문제
- **자기 포탄에 맞는 문제**: 포탄이 포신 끝에서 생성되자마자 내 탱크 콜라이더에 닿을 수 있음
  → `FireCannon`에서 생성 직후 `owner = transform.root`를 기록하고, `Cannon`에서 `other.transform.IsChildOf(owner)`면 무시
- **폭발·데미지 중복 문제**: `Start()`의 3초 타이머와 충돌 시 0초 폭발이 둘 다 실행되고, 여러 콜라이더에 닿으면 데미지가 여러 번 들어갈 수 있었음
  → `isExploded` 플래그로 한 번만 처리하고, 충돌 시 `StopAllCoroutines()`로 3초 타이머 취소

### 직접 / AI 구분
- **직접**: Unity에서 탱크에 `TankHealth` 컴포넌트 연결, 테스트
- **AI 도움**: 설계, `TankHealth.cs` 작성, `Cannon.cs`/`FireCannon.cs` 수정(자기 피격 방지, 중복 폭발 방지)

## 3. 적 AI 탱크 3종

- **요구사항**: 2-3 적 탱크 추가 (2종류 이상, 외형/체력/공격력/사거리/이동속도 다르게)
- **스크립트**: `EnemyTank.cs`, `Ballistics.cs` (신규), `Editor/EnemyPrefabBuilder.cs` (신규), `Cannon.cs` (수정)
- **상태**: ✅ 완료 (3종 배치 후 추적·조준·사격·파괴 확인)

### 적 종류
| 종류 | 외형 | HP | 이동 속도 | 사거리 | 공격력 | 연사 간격 | 특징 |
|---|---|---|---|---|---|---|---|
| 정찰형 (Scout) | 모래색, 0.8배 | 60 | 16 | 110 | 5 | 3초 | 빠르게 접근해서 자주 쏨 |
| 중전차 (Heavy) | 적갈색, 1.25배 | 250 | 6 | 90 | 15 | 5초 | 느리지만 단단하고 한 방이 셈 |
| 자주포 (Artillery) | 청회색, 1배 | 90 | 8 | 260 | 20 | 8초 | 멀리서 곡사 포격, 가까이 오면 후진 |

### 구현 방법
1. **AI 상태 판단 (`EnemyTank.Update`)**
   - 플레이어와의 거리를 재서, `stopDistance`보다 멀면 차체를 플레이어 쪽으로 돌리며 전진, 가까우면 정지
   - 자주포는 `retreatDistance`보다 가까우면 후진해서 거리를 벌림
   - 사거리 안이고, 조준이 맞고, 연사 간격이 지났으면 발사
2. **탄도 계산 (`Ballistics.TryGetLaunchAngle`)**: 포탄 속도가 정해져 있을 때, 목표를 맞히는 발사 각도를 포물선 공식으로 구한다.
   - tanθ = (v² ± √(v⁴ − g(g·x² + 2·y·v²))) / (g·x)  (x: 수평 거리, y: 높이 차)
   - `+`는 높은 탄도(곡사, 자주포), `−`는 낮은 탄도(직사, 정찰형·중전차)
   - 루트 안이 음수면 사거리 밖 → 발사하지 않음
   - 같은 함수를 나중에 **지도 포격** 기능에서도 재사용
3. **포탑·포신 조준**: 계산한 발사 방향을 포탑 기준 로컬 좌표로 바꿔(`InverseTransformDirection`) 좌우 각도는 포탑에, 상하 각도는 포신에 적용 (수업의 `TurretCtrl`과 같은 원리)
4. **명중 오차**: 발사 방향을 `spread` 각도 안에서 무작위로 비틀어 매번 정확히 맞지는 않게 함
5. **적끼리 오인 사격 방지**: `Cannon`에서 쏜 쪽과 맞은 쪽이 둘 다 적이면 데미지 없음
6. **포탄 발사 방식 변경**: `AddForce(6000)` → `linearVelocity = forward × launchSpeed(120)`
   - 같은 속도(6000 × 0.02초 ÷ 질량 1 = 120m/s)라 플레이어 사격 느낌은 그대로, 속도가 정확히 정해져서 탄도 계산이 맞음
7. **프리팹 자동 생성**: 에디터 메뉴 `Tools > TankAttack > Build Enemy Prefabs`로 원본 탱크 모델에 Rigidbody, 콜라이더, 체력, AI, 색 입힌 머티리얼을 붙여 3종을 `Resources/Enemies`에 생성

```csharp
// 탄도 계산 핵심
float root = v2 * v2 - g * (g * x * x + 2.0f * y * v2);
if (root < 0.0f) return false;              // 사거리 밖
float tanTheta = highArc ? (v2 + Mathf.Sqrt(root)) / (g * x)
                         : (v2 - Mathf.Sqrt(root)) / (g * x);
angleDeg = Mathf.Atan(tanTheta) * Mathf.Rad2Deg;
```

### 직접 / AI 구분
- **직접**: 프리팹 생성 메뉴 실행, 씬 배치, 테스트
- **AI 도움**: 적 종류와 스펙 설계, `EnemyTank.cs`·`Ballistics.cs`·`EnemyPrefabBuilder.cs` 작성, `Cannon.cs` 발사 방식 변경과 오인 사격 방지

## 4. 웨이브 매니저 · 승패 판정

- **요구사항**: 2-4 난이도 조절 (Wave 형식), 3 엔딩 씬 연결의 기반
- **스크립트**: `WaveManager.cs` (신규)
- **상태**: ✅ 완료 (5웨이브 진행, 소환 위치, 밸런스 확인)

### 웨이브 구성 (난이도 상승)
| 웨이브 | 정찰형 | 중전차 | 자주포 | 합계 |
|---|---|---|---|---|
| 1 | 3 | - | - | 3 |
| 2 | 4 | 1 | - | 5 |
| 3 | 3 | 2 | 1 | 6 |
| 4 | 4 | 2 | 2 | 8 |
| 5 | 5 | 3 | 3 | 11 (소환 간격도 짧아짐) |

### 구현 방법
1. **코루틴으로 진행 흐름 관리** (`RunWaves`)
   - 시작 대기 → 웨이브 시작 → 적을 한 마리씩 소환 → 전부 처치될 때까지 `WaitUntil` → 휴식 → 다음 웨이브
   - 마지막 웨이브를 클리어하면 승리
2. **소환 위치**: 플레이어를 중심으로 반지름 180~240m 원 위의 무작위 지점
   - `Terrain.SampleHeight()`로 지형 높이에 맞추고, 맵 밖으로 나가지 않게 `Mathf.Clamp`
   - 소환된 적은 플레이어를 바라보는 방향으로 생성
3. **소환 순서 섞기**: 같은 종류가 몰려 나오지 않게 Fisher–Yates 셔플
4. **처치 집계**: 적이 죽을 때 `EnemyTank.OnEnemyDied` 정적 이벤트가 발생 → 남은 적 수 감소
5. **패배 판정**: 플레이어 `TankHealth.OnDeath` 이벤트를 구독해서 HP가 0이 되면 패배
6. **엔딩 씬 이동**: 2초 뒤 `scWin` / `scLose` 씬으로 이동 (Build Settings에 등록된 경우만)
7. 웨이브 구성은 `List<Wave>`로 Inspector에서 수정 가능 → 밸런스 조절이 쉬움
8. UI용 이벤트(`OnWaveStarted`, `OnEnemiesLeftChanged`, `OnBreakStarted`, `OnGameEnded`)를 제공. 직접 만들 UI가 완성되기 전까지는 `OnGUI` 임시 표시 사용

```csharp
for (int i = 0; i < waves.Count; i++)
{
    // 적 소환
    foreach (EnemyTank.EnemyType type in BuildSpawnOrder(wave))
    {
        Spawn(type);
        yield return new WaitForSeconds(wave.spawnInterval);
    }
    // 이번 웨이브 적이 모두 처치될 때까지 대기
    yield return new WaitUntil(() => EnemiesLeft <= 0 || IsGameOver);
    // 휴식 후 다음 웨이브
    yield return new WaitForSeconds(breakTime);
}
EndGame(true); // 모든 웨이브 클리어 → 승리
```

### 해결한 문제
- **적 일부가 나타나지 않아 웨이브가 진행되지 않음** (테스트 중 직접 발견)
  - 원인: 맵 가장자리가 높은 산이라, 맵 밖으로 나간 소환 위치를 가장자리로 밀어 넣으면 산비탈에 소환되어 뒤집히거나 끼어서 오지 못함
  - 해결: 소환 후보를 최대 40번 뽑으면서 맵 밖·급경사(`TerrainData.GetSteepness`)·플레이어와 높이 차가 큰 곳은 제외, 계속 실패하면 반경을 줄임
  - 추가 안전장치: 적이 뒤집히거나 지형 아래로 빠진 상태가 2초 넘으면 똑바로 세워 땅 위로 복구 (`EnemyTank.CheckStuck`)
  - 화면에 적 위치·거리 표시 (화면 밖이면 가장자리에 방향 표시)
- **난이도가 너무 높음** (테스트 중 직접 발견: 연사 제한 없이도 2~3웨이브에서 패배)
  - 원인: 적의 탄도 계산이 정확해서 거의 다 명중, 3웨이브만 돼도 초당 피해가 약 30 → 플레이어 HP 100은 몇 초 만에 소진
  - 해결: 플레이어 HP 100 → 300, 웨이브 클리어 시 최대 HP의 30% 회복, 적 공격력 약 40% 감소·연사 간격 증가·명중 오차 증가
  - Inspector에서 바로 조절할 수 있게 `playerMaxHp`, `healOnWaveClear`, `enemyDamageScale`, `enemyHpScale` 추가

### 직접 / AI 구분
- **직접**: 씬에 WaveManager 배치, 테스트, 적이 안 나타나는 문제와 난이도 문제 발견
- **AI 도움**: 웨이브 구성 설계, `WaveManager.cs` 작성

## 5. 마우스 시점 카메라

- **요구사항**: 플레이어 탱크 조작 개선 (테스트 중 조작이 어렵다는 문제를 직접 발견)
- **스크립트**: `TankCamera.cs` (신규), `TurretCtrl.cs` (수정)
- **상태**: ✅ 완료

### 문제
수업의 `SmoothFollow`는 탱크 차체 방향만 따라가서, 포탑을 돌려도 카메라가 같이 돌지 않아 조준이 어려웠다.
그렇다고 카메라를 포탑에 그대로 붙이면, 포탑은 마우스가 가리키는 지점을 따라가고 그 지점은 다시 카메라를 따라 움직여서 계속 회전하는 문제가 생긴다.

### 구현 방법 (월드 오브 탱크 방식)
1. **카메라**: 마우스 이동량(`Mouse X/Y`)으로 탱크 주위를 회전하는 3인칭 카메라. 차체 방향과는 독립
   - 커서를 잠그고(`Cursor.lockState`) 화면 중앙에 조준점 표시, Esc로 해제
   - 카메라가 언덕 속으로 들어가지 않도록 지형에 Raycast해서 막히면 앞으로 당김
2. **포탑**: 마우스 위치 대신 **화면 중앙(조준점)**에서 Ray를 쏴서 그 지점으로 회전 (`ViewportPointToRay(0.5, 0.5)`)
   - 하늘을 보고 있어 지형에 안 맞으면 Ray 방향의 먼 지점을 목표로 함
3. 포신 상하는 그대로 마우스 휠(`CannonCtrl`)

```csharp
// TankCamera: 마우스로 시점 회전
yaw += Input.GetAxis("Mouse X") * mouseSensitivity;
pitch -= Input.GetAxis("Mouse Y") * mouseSensitivity;
Quaternion rot = Quaternion.Euler(pitch, yaw, 0.0f);
Vector3 camPos = pivot - rot * Vector3.forward * distance;

// TurretCtrl: 화면 중앙 기준으로 조준
```

### 구현 방법
1. 포탄 성능을 `ShellType` 클래스 배열로 정의 → Inspector에서 수치 수정 가능
2. 숫자키(`KeyCode.Alpha1 + i`)로 포탄 교체. 교체하면 새 포탄을 장전해야 해서 재장전 시간이 다시 시작

4. 발사할 때 생성한 포탄(`Cannon`)에 데미지, 범위, 속도를 넘기고, `TrailRenderer` 색과 굵기를 바꿔 종류를 눈으로 구분
5. **범위 피해(고폭탄)**: 폭발 지점에서 `Physics.OverlapSphere`로 반경 안의 콜라이더를 모두 찾음
   - 한 탱크에 콜라이더가 여러 개일 수 있어 `HashSet`으로 중복 제거
   - 거리에 따라 피해 감소: 폭심 100% → 가장자리 30% (`Mathf.Lerp`)
   - 자기 자신과 아군은 제외
6. 공격력 아이템을 위해 `damageMultiplier` 변수 준비

```csharp
// 범위 피해
foreach (Collider col in Physics.OverlapSphere(transform.position, splashRadius))
{
    TankHealth health = col.GetComponentInParent<TankHealth>();
    if (health == null || !damaged.Add(health)) continue;   // 중복 제거
    float dist = Vector3.Distance(transform.position, col.ClosestPoint(transform.position));
    float falloff = Mathf.Lerp(1.0f, 0.3f, dist / splashRadius); // 멀수록 약하게
    health.TakeDamage(damage * falloff);
}
```

## 7. 조준 방식 개선 · 정밀 조준 모드 (나만의 기능)

- **요구사항**: 2-6 본인이 추가하고 싶은 기능
- **스크립트**: `TankCamera.cs`, `TurretCtrl.cs`, `CannonCtrl.cs`, `FireCannon.cs` (수정)
- **상태**: ✅ 완료 (일반/정밀 조준, 줌, 탄도 보정 확인)

### 기획 (직접)
- 마우스로 좌우, 휠로 상하를 따로 조절하던 방식을 없애고 **화면 조준점 하나로 상하좌우를 모두 조준**
- 정밀 조준(우클릭)이 의미 있도록 두 모드의 역할을 나눔 (A안)

| | 일반 조준 | 우클릭 정밀 조준 |
|---|---|---|
| 포신 | 조준점을 직선으로 겨눔 (낙차 보정 없음, 먼 적은 감으로 위를 겨눠야 함) | 조준점에 떨어지도록 탄도 자동 계산 |
| 시야 | 3인칭, FOV 60 | 포탑 위 조준경 시점, FOV 15 (4배 줌) |
| 마우스 감도 | 기본 | 줌 비율만큼 낮춤 |
| 명중 오차 | 1.5° | 0.2° |
| 화면 | `+` 조준점 | 빨간 십자선 + 거리 표시 |

### 구현 방법
1. **조준점 계산 (`TankCamera.UpdateAimPoint`)**: 카메라 정면으로 `RaycastAll`을 쏴서 내 탱크와 포탄(Trigger)을 제외한 가장 가까운 지점을 `AimPoint`로 저장. 지형뿐 아니라 적 탱크도 조준 가능
2. **포탑 (`TurretCtrl`)**: 수업 코드 구조(`InverseTransformPoint` → `Atan2`)를 그대로 쓰고, 목표 지점만 `AimPoint`로 변경
3. **포신 (`CannonCtrl`)**: 마우스 휠 입력 대신 조준점 기준 목표 각도를 구해 `Mathf.MoveTowards`로 서서히 움직임
   - 일반: 포신 → 조준점 직선 방향
   - 정밀: `Ballistics.TryGetLaunchAngle`로 현재 포탄 속도 기준 발사 각도 계산 (사거리 밖이면 45도)
   - 구한 방향을 포탑 기준 로컬 좌표로 바꿔 높이 각도 계산 (차체 기울기 보정)
   - **직접 작성했던 `currAngle` 변수 + `Mathf.Clamp` 각도 제한 구조는 그대로 유지** → 요구사항 "포신 각도 조절(제한)" 유지
4. **정밀 조준 카메라 (`TankCamera`)**: 우클릭 유지 시 포탑 위 조준경 위치로 이동, `fieldOfView`를 `Lerp`로 줄여 줌인, 감도를 `현재 FOV / 기본 FOV` 비율로 낮춤
5. **명중 오차 (`FireCannon`)**: 발사 방향을 모드별 오차 범위 안에서 무작위로 비틂

```csharp
// CannonCtrl: 휠 대신 조준점 기준 목표 각도로 이동 + 각도 제한
float targetAngle = GetTargetAngle();
currAngle = Mathf.MoveTowards(currAngle, targetAngle, rotSpeed * Time.deltaTime);
currAngle = Mathf.Clamp(currAngle, minAngle, maxAngle);
tr.localRotation = Quaternion.Euler(currAngle, 0.0f, 0.0f);

// 정밀 조준일 때만 탄도 계산
if (tankCam.IsPrecision &&
    Ballistics.TryGetLaunchAngle(tr.position, aimPoint, speed, false, out float launchAngle))
{
    dir = Ballistics.GetLaunchDirection(tr.position, aimPoint, launchAngle);
}
```

- **상태**: ✅ 완료 (포탄 착탄 폭발, 적·플레이어 파괴 폭발 확인)

### 해결한 문제: URP 전용 에셋 호환
- **증상**: 임포트한 폭발 이펙트가 분홍색으로 보임 (직접 발견)
- **원인**: 이 에셋의 머티리얼은 **URP 전용 셰이더**를 사용하는데, 수업 예제 프로젝트는 **Built-in 렌더러**라 해당 셰이더가 없음
- **검토한 방법**
  - Render Pipeline Converter로 프로젝트 전체를 URP로 변환 → Built-in → URP 방향만 지원, 눈 에셋의 커스텀 셰이더 등 다른 에셋이 깨질 위험, 기말 예제와도 달라짐 → **기각**
  - 다른 폭발 에셋 사용 → 차별화를 위해 이 에셋을 살리기로 결정
  - **폭발 머티리얼만 Built-in 셰이더로 변환** → 채택
- **방법**: 에디터 메뉴 `Tools > TankAttack > Convert Explosion Materials to Built-in`
  - 셰이더가 없어도 머티리얼 파일에 남아 있는 원래 텍스처(`_BaseMap`) 값을 `SerializedObject`로 읽어서 옮김
  - 불꽃·스파크는 `Legacy Shaders/Particles/Additive`, 연기는 `Alpha Blended`, 불투명 데모 머티리얼은 `Standard`

### 포탄 폭발 연결 (직접)
- `Resources/Cannon` 프리팹의 `Exp Effect`에 작은 폭발 프리팹 연결
- 새 폭발은 1초보다 길어서 중간에 잘림 → `Cannon.cs`의 `Destroy(obj, 1.0f)`를 3초로 직접 수정

### 탱크 파괴 폭발 (구조 제시 → 직접 작성)
- 에셋에 큰 폭발이 따로 없어서, 폭발 Variant를 복제해 Scale을 키우고 파티클 Scaling Mode를 Hierarchy로 바꿔 `Resources/TankExplosion` 제작
- 공용 체력 스크립트 `TankHealth`의 `Die()`에서 폭발 생성 → 적과 플레이어 모두 파괴 시 폭발
- `Resources.Load`로 코드에서 불러와 프리팹마다 따로 연결할 필요 없음

```csharp
deathEffect = Resources.Load<GameObject>("TankExplosion");   // Awake
...
if (deathEffect != null)                                        // Die
{
    GameObject effect = Instantiate(deathEffect, transform.position + Vector3.up * 2.0f, Quaternion.identity);
    Destroy(effect, 3.0f);
}
OnDeath?.Invoke();
```

- **직접 수정**: 처음에 `Resources.Load`의 이름을 프리팹 이름과 다르게 적어 폭발이 안 나옴 → `Resources.Load`는 이름이 틀려도 에러 없이 null을 돌려준다는 점을 확인하고 이름을 맞춰 해결
