## 1. 포신 각도 제한

- **요구사항**: 2-2 플레이어 탱크 기능 추가 (포신 각도 조절 제한)
- **스크립트**: `Assets/02.Scripts/CannonCtrl.cs`
- **상태**: ✅ 완료

### 문제
수업 버전은 휠 입력만큼 `tr.Rotate(angle, 0, 0)`으로 회전을 계속 더하기만 해서, 포신이 위아래로 끝없이 돌아 차체와 땅을 뚫고 한 바퀴를 돌았다.

### 구현 방법
1. 포신의 현재 각도를 변수 `currAngle`에 직접 저장한다.
2. 휠 입력만큼 `currAngle`에 더한다.
3. `Mathf.Clamp`로 `minAngle ~ maxAngle` 범위를 넘지 않게 자른다.
4. 자른 각도를 `localRotation`에 **덮어쓴다** (`Rotate`처럼 누적하지 않음).

```csharp
float currAngle = 0.0f;
public float minAngle = -20.0f;   // 위쪽 한계 (Unity X축 회전은 음수가 위쪽)
public float maxAngle = 20.0f;    // 아래쪽 한계

void Update()
{
    float angle = -Input.GetAxis("Mouse ScrollWheel") * Time.deltaTime * rotSpeed;
    currAngle += angle;
    currAngle = Mathf.Clamp(currAngle, minAngle, maxAngle);
    tr.localRotation = Quaternion.Euler(currAngle, 0.0f, 0.0f);
}
```

### 포인트
- `transform.localEulerAngles.x`를 읽어서 쓰면 -10°가 350°로 나와 Clamp가 깨지므로, 각도를 직접 변수로 관리했다.
- `localRotation`은 `Quaternion` 타입이라 `Quaternion.Euler()`로 변환해서 대입했다.
- `minAngle`, `maxAngle`을 `public`으로 열어 Inspector에서 조절할 수 있게 했다.

### 직접 / AI 구분
- **직접**: `CannonCtrl.cs` 코드 작성, 각도 범위 설정과 테스트
- **AI 도움**: 구현 방향 힌트(변수 저장 → Clamp → 덮어쓰기), `Vector3`를 `localRotation`에 넣어 생긴 타입 오류 원인 설명, Clamp 반환값 미사용과 실행 순서 문제 지적, 최종 코드 리뷰

## 2. HP · 데미지 시스템

- **요구사항**: 적 AI, 아이템(HP 회복), 승리·패배 판정의 기반
- **스크립트**: `TankHealth.cs` (신규), `Cannon.cs`, `FireCannon.cs` (수정)
- **상태**: ✅ 완료 (큐브 표적으로 피격·파괴 확인)

### 구현 방법
1. `TankHealth` 컴포넌트를 플레이어와 적 탱크에 공통으로 붙인다.
   - `maxHp`, `currHp`, `TakeDamage()`, `Heal()`, `Die()`
   - 체력은 `Mathf.Clamp`로 0 ~ maxHp 범위 유지
   - `OnHpChanged`, `OnDeath` 이벤트를 두어 HP바 UI와 게임 매니저(패배 처리)가 나중에 구독할 수 있게 함
2. 포탄(`Cannon`)이 `OnTriggerEnter`에서 맞은 대상의 `TankHealth`를 찾아 `TakeDamage(damage)` 호출
   - 콜라이더가 탱크의 자식에 있을 수 있어 `GetComponentInParent<TankHealth>()` 사용, 지형에 맞으면 null이라 무시

```csharp
TankHealth health = other.GetComponentInParent<TankHealth>();
if (health != null)
{
    health.TakeDamage(damage);
}
```

### 해결한 문제
- **자기 포탄에 맞는 문제**: 포탄이 포신 끝에서 생성되자마자 내 탱크 콜라이더에 닿을 수 있음
  → `FireCannon`에서 생성 직후 `owner = transform.root`를 기록하고, `Cannon`에서 `other.transform.IsChildOf(owner)`면 무시
- **폭발·데미지 중복 문제**: `Start()`의 3초 타이머와 충돌 시 0초 폭발이 둘 다 실행되고, 여러 콜라이더에 닿으면 데미지가 여러 번 들어갈 수 있었음
  → `isExploded` 플래그로 한 번만 처리하고, 충돌 시 `StopAllCoroutines()`로 3초 타이머 취소

### 직접 / AI 구분
- **직접**: Unity에서 탱크에 `TankHealth` 컴포넌트 연결, 테스트
- **AI 도움**: 설계, `TankHealth.cs` 작성, `Cannon.cs`/`FireCannon.cs` 수정(자기 피격 방지, 중복 폭발 방지)

## 3. 적 AI 탱크 3종

- **요구사항**: 2-3 적 탱크 추가 (2종류 이상, 외형/체력/공격력/사거리/이동속도 다르게)
- **스크립트**: `EnemyTank.cs`, `Ballistics.cs` (신규), `Editor/EnemyPrefabBuilder.cs` (신규), `Cannon.cs` (수정)
- **상태**: ✅ 완료 (3종 배치 후 추적·조준·사격·파괴 확인)

### 적 종류
| 종류 | 외형 | HP | 이동 속도 | 사거리 | 공격력 | 연사 간격 | 특징 |
|---|---|---|---|---|---|---|---|
| 정찰형 (Scout) | 모래색, 0.8배 | 60 | 16 | 110 | 5 | 3초 | 빠르게 접근해서 자주 쏨 |
| 중전차 (Heavy) | 적갈색, 1.25배 | 250 | 6 | 90 | 15 | 5초 | 느리지만 단단하고 한 방이 셈 |
| 자주포 (Artillery) | 청회색, 1배 | 90 | 8 | 260 | 20 | 8초 | 멀리서 곡사 포격, 가까이 오면 후진 |

### 구현 방법
1. **AI 상태 판단 (`EnemyTank.Update`)**
   - 플레이어와의 거리를 재서, `stopDistance`보다 멀면 차체를 플레이어 쪽으로 돌리며 전진, 가까우면 정지
   - 자주포는 `retreatDistance`보다 가까우면 후진해서 거리를 벌림
   - 사거리 안이고, 조준이 맞고, 연사 간격이 지났으면 발사
2. **탄도 계산 (`Ballistics.TryGetLaunchAngle`)**: 포탄 속도가 정해져 있을 때, 목표를 맞히는 발사 각도를 포물선 공식으로 구한다.
   - tanθ = (v² ± √(v⁴ − g(g·x² + 2·y·v²))) / (g·x)  (x: 수평 거리, y: 높이 차)
   - `+`는 높은 탄도(곡사, 자주포), `−`는 낮은 탄도(직사, 정찰형·중전차)
   - 루트 안이 음수면 사거리 밖 → 발사하지 않음
   - 같은 함수를 나중에 **지도 포격** 기능에서도 재사용
3. **포탑·포신 조준**: 계산한 발사 방향을 포탑 기준 로컬 좌표로 바꿔(`InverseTransformDirection`) 좌우 각도는 포탑에, 상하 각도는 포신에 적용 (수업의 `TurretCtrl`과 같은 원리)
4. **명중 오차**: 발사 방향을 `spread` 각도 안에서 무작위로 비틀어 매번 정확히 맞지는 않게 함
5. **적끼리 오인 사격 방지**: `Cannon`에서 쏜 쪽과 맞은 쪽이 둘 다 적이면 데미지 없음
6. **포탄 발사 방식 변경**: `AddForce(6000)` → `linearVelocity = forward × launchSpeed(120)`
   - 같은 속도(6000 × 0.02초 ÷ 질량 1 = 120m/s)라 플레이어 사격 느낌은 그대로, 속도가 정확히 정해져서 탄도 계산이 맞음
7. **프리팹 자동 생성**: 에디터 메뉴 `Tools > TankAttack > Build Enemy Prefabs`로 원본 탱크 모델에 Rigidbody, 콜라이더, 체력, AI, 색 입힌 머티리얼을 붙여 3종을 `Resources/Enemies`에 생성

```csharp
// 탄도 계산 핵심
float root = v2 * v2 - g * (g * x * x + 2.0f * y * v2);
if (root < 0.0f) return false;              // 사거리 밖
float tanTheta = highArc ? (v2 + Mathf.Sqrt(root)) / (g * x)
                         : (v2 - Mathf.Sqrt(root)) / (g * x);
angleDeg = Mathf.Atan(tanTheta) * Mathf.Rad2Deg;
```

### 직접 / AI 구분
- **직접**: 프리팹 생성 메뉴 실행, 씬 배치, 테스트
- **AI 도움**: 적 종류와 스펙 설계, `EnemyTank.cs`·`Ballistics.cs`·`EnemyPrefabBuilder.cs` 작성, `Cannon.cs` 발사 방식 변경과 오인 사격 방지

## 4. 웨이브 매니저 · 승패 판정

- **요구사항**: 2-4 난이도 조절 (Wave 형식), 3 엔딩 씬 연결의 기반
- **스크립트**: `WaveManager.cs` (신규)
- **상태**: ✅ 완료 (5웨이브 진행, 소환 위치, 밸런스 확인)

### 웨이브 구성 (난이도 상승)
| 웨이브 | 정찰형 | 중전차 | 자주포 | 합계 |
|---|---|---|---|---|
| 1 | 3 | - | - | 3 |
| 2 | 4 | 1 | - | 5 |
| 3 | 3 | 2 | 1 | 6 |
| 4 | 4 | 2 | 2 | 8 |
| 5 | 5 | 3 | 3 | 11 (소환 간격도 짧아짐) |

### 구현 방법
1. **코루틴으로 진행 흐름 관리** (`RunWaves`)
   - 시작 대기 → 웨이브 시작 → 적을 한 마리씩 소환 → 전부 처치될 때까지 `WaitUntil` → 휴식 → 다음 웨이브
   - 마지막 웨이브를 클리어하면 승리
2. **소환 위치**: 플레이어를 중심으로 반지름 180~240m 원 위의 무작위 지점
   - `Terrain.SampleHeight()`로 지형 높이에 맞추고, 맵 밖으로 나가지 않게 `Mathf.Clamp`
   - 소환된 적은 플레이어를 바라보는 방향으로 생성
3. **소환 순서 섞기**: 같은 종류가 몰려 나오지 않게 Fisher–Yates 셔플
4. **처치 집계**: 적이 죽을 때 `EnemyTank.OnEnemyDied` 정적 이벤트가 발생 → 남은 적 수 감소
5. **패배 판정**: 플레이어 `TankHealth.OnDeath` 이벤트를 구독해서 HP가 0이 되면 패배
6. **엔딩 씬 이동**: 2초 뒤 `scWin` / `scLose` 씬으로 이동 (Build Settings에 등록된 경우만)
7. 웨이브 구성은 `List<Wave>`로 Inspector에서 수정 가능 → 밸런스 조절이 쉬움
8. UI용 이벤트(`OnWaveStarted`, `OnEnemiesLeftChanged`, `OnBreakStarted`, `OnGameEnded`)를 제공. 직접 만들 UI가 완성되기 전까지는 `OnGUI` 임시 표시 사용

```csharp
for (int i = 0; i < waves.Count; i++)
{
    // 적 소환
    foreach (EnemyTank.EnemyType type in BuildSpawnOrder(wave))
    {
        Spawn(type);
        yield return new WaitForSeconds(wave.spawnInterval);
    }
    // 이번 웨이브 적이 모두 처치될 때까지 대기
    yield return new WaitUntil(() => EnemiesLeft <= 0 || IsGameOver);
    // 휴식 후 다음 웨이브
    yield return new WaitForSeconds(breakTime);
}
EndGame(true); // 모든 웨이브 클리어 → 승리
```

### 해결한 문제
- **적 일부가 나타나지 않아 웨이브가 진행되지 않음** (테스트 중 직접 발견)
  - 원인: 맵 가장자리가 높은 산이라, 맵 밖으로 나간 소환 위치를 가장자리로 밀어 넣으면 산비탈에 소환되어 뒤집히거나 끼어서 오지 못함
  - 해결: 소환 후보를 최대 40번 뽑으면서 맵 밖·급경사(`TerrainData.GetSteepness`)·플레이어와 높이 차가 큰 곳은 제외, 계속 실패하면 반경을 줄임
  - 추가 안전장치: 적이 뒤집히거나 지형 아래로 빠진 상태가 2초 넘으면 똑바로 세워 땅 위로 복구 (`EnemyTank.CheckStuck`)
  - 화면에 적 위치·거리 표시 (화면 밖이면 가장자리에 방향 표시)
- **난이도가 너무 높음** (테스트 중 직접 발견: 연사 제한 없이도 2~3웨이브에서 패배)
  - 원인: 적의 탄도 계산이 정확해서 거의 다 명중, 3웨이브만 돼도 초당 피해가 약 30 → 플레이어 HP 100은 몇 초 만에 소진
  - 해결: 플레이어 HP 100 → 300, 웨이브 클리어 시 최대 HP의 30% 회복, 적 공격력 약 40% 감소·연사 간격 증가·명중 오차 증가
  - Inspector에서 바로 조절할 수 있게 `playerMaxHp`, `healOnWaveClear`, `enemyDamageScale`, `enemyHpScale` 추가

## 5. 마우스 시점 카메라

- **요구사항**: 플레이어 탱크 조작 개선 (테스트 중 조작이 어렵다는 문제를 직접 발견)
- **스크립트**: `TankCamera.cs` (신규), `TurretCtrl.cs` (수정)
- **상태**: ✅ 완료

### 문제
수업의 `SmoothFollow`는 탱크 차체 방향만 따라가서, 포탑을 돌려도 카메라가 같이 돌지 않아 조준이 어려웠다.
그렇다고 카메라를 포탑에 그대로 붙이면, 포탑은 마우스가 가리키는 지점을 따라가고 그 지점은 다시 카메라를 따라 움직여서 계속 회전하는 문제가 생긴다.

### 구현 방법 (월드 오브 탱크 방식)
1. **카메라**: 마우스 이동량(`Mouse X/Y`)으로 탱크 주위를 회전하는 3인칭 카메라. 차체 방향과는 독립
   - 커서를 잠그고(`Cursor.lockState`) 화면 중앙에 조준점 표시, Esc로 해제
   - 카메라가 언덕 속으로 들어가지 않도록 지형에 Raycast해서 막히면 앞으로 당김
2. **포탑**: 마우스 위치 대신 **화면 중앙(조준점)**에서 Ray를 쏴서 그 지점으로 회전 (`ViewportPointToRay(0.5, 0.5)`)
   - 하늘을 보고 있어 지형에 안 맞으면 Ray 방향의 먼 지점을 목표로 함
3. 포신 상하는 그대로 마우스 휠(`CannonCtrl`)

```csharp
// TankCamera: 마우스로 시점 회전
yaw += Input.GetAxis("Mouse X") * mouseSensitivity;
pitch -= Input.GetAxis("Mouse Y") * mouseSensitivity;
Quaternion rot = Quaternion.Euler(pitch, yaw, 0.0f);
Vector3 camPos = pivot - rot * Vector3.forward * distance;

// TurretCtrl: 화면 중앙 기준으로 조준
Ray ray = Camera.main.ViewportPointToRay(new Vector3(0.5f, 0.5f, 0.0f));
```

- **AI 도움**: 카메라-포탑 순환 문제 설명, `TankCamera.cs` 작성, `TurretCtrl.cs` 조준 기준 변경

### 구현 방법
1. 포탄 성능을 `ShellType` 클래스 배열로 정의 → Inspector에서 수치 수정 가능
2. 숫자키(`KeyCode.Alpha1 + i`)로 포탄 교체. 교체하면 새 포탄을 장전해야 해서 재장전 시간이 다시 시작

4. 발사할 때 생성한 포탄(`Cannon`)에 데미지, 범위, 속도를 넘기고, `TrailRenderer` 색과 굵기를 바꿔 종류를 눈으로 구분
5. **범위 피해(고폭탄)**: 폭발 지점에서 `Physics.OverlapSphere`로 반경 안의 콜라이더를 모두 찾음
   - 한 탱크에 콜라이더가 여러 개일 수 있어 `HashSet`으로 중복 제거
   - 거리에 따라 피해 감소: 폭심 100% → 가장자리 30% (`Mathf.Lerp`)
   - 자기 자신과 아군은 제외
6. 공격력 아이템을 위해 `damageMultiplier` 변수 준비

```csharp
// 범위 피해
foreach (Collider col in Physics.OverlapSphere(transform.position, splashRadius))
{
    TankHealth health = col.GetComponentInParent<TankHealth>();
    if (health == null || !damaged.Add(health)) continue;   // 중복 제거
    float dist = Vector3.Distance(transform.position, col.ClosestPoint(transform.position));
    float falloff = Mathf.Lerp(1.0f, 0.3f, dist / splashRadius); // 멀수록 약하게
    health.TakeDamage(damage * falloff);
}
```

## 7. 조준 방식 개선 · 정밀 조준 모드 (나만의 기능)

- **요구사항**: 2-6 본인이 추가하고 싶은 기능
- **스크립트**: `TankCamera.cs`, `TurretCtrl.cs`, `CannonCtrl.cs`, `FireCannon.cs` (수정)
- **상태**: ✅ 완료 (일반/정밀 조준, 줌, 탄도 보정 확인)

### 기획 (직접)
- 마우스로 좌우, 휠로 상하를 따로 조절하던 방식을 없애고 **화면 조준점 하나로 상하좌우를 모두 조준**
- 정밀 조준(우클릭)이 의미 있도록 두 모드의 역할을 나눔 (A안)

| | 일반 조준 | 우클릭 정밀 조준 |
|---|---|---|
| 포신 | 조준점을 직선으로 겨눔 (낙차 보정 없음, 먼 적은 감으로 위를 겨눠야 함) | 조준점에 떨어지도록 탄도 자동 계산 |
| 시야 | 3인칭, FOV 60 | 포탑 위 조준경 시점, FOV 15 (4배 줌) |
| 마우스 감도 | 기본 | 줌 비율만큼 낮춤 |
| 명중 오차 | 1.5° | 0.2° |
| 화면 | `+` 조준점 | 빨간 십자선 + 거리 표시 |

### 구현 방법
1. **조준점 계산 (`TankCamera.UpdateAimPoint`)**: 카메라 정면으로 `RaycastAll`을 쏴서 내 탱크와 포탄(Trigger)을 제외한 가장 가까운 지점을 `AimPoint`로 저장. 지형뿐 아니라 적 탱크도 조준 가능
2. **포탑 (`TurretCtrl`)**: 수업 코드 구조(`InverseTransformPoint` → `Atan2`)를 그대로 쓰고, 목표 지점만 `AimPoint`로 변경
3. **포신 (`CannonCtrl`)**: 마우스 휠 입력 대신 조준점 기준 목표 각도를 구해 `Mathf.MoveTowards`로 서서히 움직임
   - 일반: 포신 → 조준점 직선 방향
   - 정밀: `Ballistics.TryGetLaunchAngle`로 현재 포탄 속도 기준 발사 각도 계산 (사거리 밖이면 45도)
   - 구한 방향을 포탑 기준 로컬 좌표로 바꿔 높이 각도 계산 (차체 기울기 보정)
   - **직접 작성했던 `currAngle` 변수 + `Mathf.Clamp` 각도 제한 구조는 그대로 유지** → 요구사항 "포신 각도 조절(제한)" 유지
4. **정밀 조준 카메라 (`TankCamera`)**: 우클릭 유지 시 포탑 위 조준경 위치로 이동, `fieldOfView`를 `Lerp`로 줄여 줌인, 감도를 `현재 FOV / 기본 FOV` 비율로 낮춤
5. **명중 오차 (`FireCannon`)**: 발사 방향을 모드별 오차 범위 안에서 무작위로 비틂

```csharp
// CannonCtrl: 휠 대신 조준점 기준 목표 각도로 이동 + 각도 제한
float targetAngle = GetTargetAngle();
currAngle = Mathf.MoveTowards(currAngle, targetAngle, rotSpeed * Time.deltaTime);
currAngle = Mathf.Clamp(currAngle, minAngle, maxAngle);
tr.localRotation = Quaternion.Euler(currAngle, 0.0f, 0.0f);

// 정밀 조준일 때만 탄도 계산
if (tankCam.IsPrecision &&
    Ballistics.TryGetLaunchAngle(tr.position, aimPoint, speed, false, out float launchAngle))
{
    dir = Ballistics.GetLaunchDirection(tr.position, aimPoint, launchAngle);
}
```

- **직접**: 조준 방식 기획(휠 제거, 일반/정밀 역할 분리 A안 결정), 기존 `CannonCtrl` 각도 제한 구조, 테스트

### 해결한 문제: URP 전용 에셋 호환
- **증상**: 임포트한 폭발 이펙트가 분홍색으로 보임 (직접 발견)
- **원인**: 이 에셋의 머티리얼은 **URP 전용 셰이더**를 사용하는데, 수업 예제 프로젝트는 **Built-in 렌더러**라 해당 셰이더가 없음
- **검토한 방법**
  - Render Pipeline Converter로 프로젝트 전체를 URP로 변환 → Built-in → URP 방향만 지원, 눈 에셋의 커스텀 셰이더 등 다른 에셋이 깨질 위험, 기말 예제와도 달라짐 → **기각**
  - 다른 폭발 에셋 사용 → 차별화를 위해 이 에셋을 살리기로 결정
  - **폭발 머티리얼만 Built-in 셰이더로 변환** → 채택
- **방법**: 에디터 메뉴 `Tools > TankAttack > Convert Explosion Materials to Built-in`
  - 셰이더가 없어도 머티리얼 파일에 남아 있는 원래 텍스처(`_BaseMap`) 값을 `SerializedObject`로 읽어서 옮김
  - 불꽃·스파크는 `Legacy Shaders/Particles/Additive`, 연기는 `Alpha Blended`, 불투명 데모 머티리얼은 `Standard`

- `Resources/Cannon` 프리팹의 `Exp Effect`에 작은 폭발 프리팹 연결
- 새 폭발은 1초보다 길어서 중간에 잘림 → `Cannon.cs`의 `Destroy(obj, 1.0f)`를 3초로 직접 수정

### 탱크 파괴 폭발 (구조 제시 → 직접 작성)
- 에셋에 큰 폭발이 따로 없어서, 폭발 Variant를 복제해 Scale을 키우고 파티클 Scaling Mode를 Hierarchy로 바꿔 `Resources/TankExplosion` 제작

- `Resources.Load`로 코드에서 불러와 프리팹마다 따로 연결할 필요 없음

```csharp
deathEffect = Resources.Load<GameObject>("TankExplosion");   // Awake
...
if (deathEffect != null)                                        // Die
{
    GameObject effect = Instantiate(deathEffect, transform.position + Vector3.up * 2.0f, Quaternion.identity);

OnDeath?.Invoke();
```

- **직접 수정**: 처음에 `Resources.Load`의 이름을 프리팹 이름과 다르게 적어 폭발이 안 나옴 → `Resources.Load`는 이름이 틀려도 에러 없이 null을 돌려준다는 점을 확인하고 이름을 맞춰 해결

## 9. 아이템 (HP · 속도 · 공격력)

- **프리팹**: `Resources/Items/Item_Heal`, `Item_Speed`, `Item_Attack`
- **상태**: ✅ 완료 (드롭, 획득, 효과, 지속 시간 확인)

### 아이템 종류
| 아이템 | 색 | 효과 |
|---|---|---|
| Item_Heal | 초록 | 체력 80 회복 (`TankHealth.Heal`, 최대 HP를 넘지 않음) |
| Item_Speed | 파랑 | 10초 동안 이동 속도 1.5배 (`TankMove.moveSpeed`) |
| Item_Attack | 빨강 | 10초 동안 공격력 1.5배 (`FireCannon.damageMultiplier`) |

### 구현 방법
1. **드롭 (`ItemDropper`)**: 적 AI 코드는 건드리지 않고, 적이 파괴될 때 발생하는 `EnemyTank.OnEnemyDied` 이벤트를 구독
   - `Random.value`로 40% 확률 판정, `Resources.LoadAll`로 `Items` 폴더의 아이템을 전부 불러와 그중 하나를 무작위로 생성
   - 아이템을 새로 추가해도 폴더에 프리팹만 넣으면 됨 (코드 수정 불필요)
2. **획득 (`Item`)**: `OnTriggerEnter`에서 `GetComponentInParent<TankMove>()`로 플레이어만 걸러 내고, `switch`로 종류별 효과 적용
3. **지속 효과**: 아이템은 먹자마자 `Destroy`되므로, 아이템에서 코루틴을 돌리면 효과가 끝나기 전에 멈춤 → **플레이어 쪽(`player.StartCoroutine`)에서 코루틴 실행**
4. 눈에 띄도록 제자리 회전, 20초 동안 안 먹으면 사라짐

```csharp
// 드롭: 적 파괴 이벤트 구독
void OnEnable()  { EnemyTank.OnEnemyDied += DropItem; }
void OnDisable() { EnemyTank.OnEnemyDied -= DropItem; }

// 획득: 지속 효과는 사라지지 않는 플레이어 쪽에서 실행
case ItemType.Speed:
    player.StartCoroutine(SpeedBuff(player));
    break;
```

  Vector3 pos = transform.position;
  pos.y = startY + Mathf.Sin(Time.time * bobSpeed) * bobHeight;

## 11. 지도 포격 (나만의 기능 2)

- **요구사항**: 2-6 본인이 추가하고 싶은 기능
- **스크립트**: `MapStrike.cs` (신규), `FireCannon.cs`, `TankCamera.cs`, `CannonCtrl.cs` (수정)
- **상태**: ✅ 완료 (지도 표시, 목표 지정, 연속 포격, 쿨타임 확인)

### 기획 (직접)
- 배틀그라운드처럼 **M키로 지도를 열고 적이 있는 곳을 클릭해서 포격**하면, 좌표를 자동 계산해서 쏴 주는 기능
- "사거리 밖"이 한계로 제시되자 "포신 각도 제한을 넓히면 되지 않나?" 질문 → 각도 확장과 속도 조절로 해결 방향 결정
- 쿨타임이 있으니 한 번에 **3~5연발**로 확실한 한 방이 되도록 결정
- 정밀 조준과 역할 구분: 일반(직사) / 정밀(보이는 적 탄도 보정) / 지도 포격(안 보이는 곳까지 자동)

### 동작
| 단계 | 내용 |
|---|---|
| 1 | **M키**: 맵 전체를 위에서 내려다보는 전술 지도 열기 (내 탱크 ▲, 적 ◆ 실시간 표시) |
| 2 | 지도 클릭: 목표 지점(✕) 지정, 거리와 사거리(최대 450m) 표시 |
| 3 | **[포격]** 버튼: 지도가 닫히고 포탑·포신이 목표 쪽으로 회전 |
| 4 | 목표 주변 8m 안으로 흩어지게 **4발 연속 발사** (0.4초 간격) |
| 5 | **25초 쿨타임** |
| + | 지도 위에서 **마우스 휠로 확대·축소** (마우스가 가리키는 곳 기준) |
| + | 지도를 **마우스로 끌어서 이동** (짧게 클릭하면 목표 지정, 누른 채 끌면 이동) |

### 구현 방법
1. **지도 카메라**: 코드에서 직교(Orthographic) 카메라를 생성해 지형 중앙 위에서 아래를 보게 하고, `Camera.rect`로 화면 가운데 영역에만 그림
   - 지도 영역의 가로세로 비율에 맞춰 `orthographicSize`를 계산해 맵 전체가 들어오게 함
   - 위에서 멀리 보면 안개 때문에 하얗게 보여서, 지도 카메라가 그릴 때만 `RenderSettings.fog`를 끄고 다시 켬 (`OnPreRender` / `OnPostRender`)
2. **지도 클릭 → 월드 좌표**: 지도 카메라 기준 `ScreenPointToRay`로 Ray를 쏴서 지형(8번 레이어)에 맞은 지점을 목표로 저장 (수업의 Raycast 응용)
3. **자동 조준**: `TankCamera.AimOverride`에 목표를 넣으면 포탑(`TurretCtrl`)과 포신(`CannonCtrl`)이 화면 중앙 대신 그 지점을 조준하고, 포신은 탄도 계산으로 각도를 맞춤
4. **발사**: `FireCannon.FireAt(target)`이 `Ballistics`로 발사 각도를 계산해서 그 방향으로 포탄 생성 (적 AI와 같은 탄도 공식 재사용)
5. **연속 포격**: 코루틴에서 `Random.insideUnitCircle`로 목표 주변 무작위 지점을 골라 정해진 간격으로 발사
6. 지도가 열려 있는 동안은 커서를 풀고 일반 사격·커서 재잠금을 막음 (`MapStrike.IsMapOpen`, `IsBusy`)

```csharp
// 지도 클릭 → 지형 좌표
Ray ray = mapCam.ScreenPointToRay(Input.mousePosition);
if (Physics.Raycast(ray, out RaycastHit hit, Mathf.Infinity, 1 << 8))
    selected = hit.point;

// 연속 포격
tankCam.AimOverride = target;                 // 포탑·포신이 목표를 향함
yield return new WaitForSeconds(aimTime);
for (int i = 0; i < salvoCount; i++)
{
    Vector2 r = Random.insideUnitCircle * scatterRadius;   // 목표 주변으로 흩어짐
    fire.FireAt(target + new Vector3(r.x, 0.0f, r.y));     // 탄도 자동 계산 발사
    yield return new WaitForSeconds(salvoInterval);
}
```

### 직접 / AI 구분
- **직접**: 기능 아이디어와 세부 기획(지도 클릭 포격, 연발, 쿨타임, 휠 확대·축소와 끌어서 이동 추가), 사거리 한계 해결 방향 제시, 테스트
- **AI 도움**: 지도 카메라·클릭 좌표 변환·연속 포격·확대 축소·끌어서 이동 설계와 코드 작성, 기존 조준 코드와 연결

### 추가: 지도 확대·축소
- 지도 카메라의 `orthographicSize`를 휠 입력만큼 줄이거나 늘림 (맵 전체 크기 ~ 최소 크기 사이로 제한)
- 확대 전후에 마우스 아래의 월드 좌표(`ScreenToWorldPoint`)를 비교해서 그 차이만큼 카메라를 옮김 → **마우스가 가리키던 지점이 화면에서 그대로 유지**
- 확대한 상태에서 지도가 맵 밖을 비추지 않도록 카메라 위치를 지형 범위 안으로 제한
- 지도를 다시 열면 맵 전체가 보이는 상태로 초기화

### 추가: 지도 끌어서 이동 (배틀그라운드 방식, 아이디어 직접)
- 같은 왼쪽 버튼으로 "목표 지정"과 "지도 이동"을 함께 처리하기 위해 **클릭과 끌기를 구분**
  - 누른 지점에서 8픽셀 이상 움직이면 끌기, 그보다 적게 움직이고 떼면 클릭(목표 지정)
- 끄는 동안 직전 프레임과 지금 마우스 위치의 월드 좌표 차이만큼 카메라를 반대로 이동 → 지도를 손으로 잡아 끄는 느낌
- 이동한 위치도 지형 범위 안으로 제한 (`ClampToTerrain` 재사용)

### 수정: 지도 위에 화면용 적 표시가 겹침 (직접 발견)
- 지도를 열어도 평소 화면에 쓰는 적 위치 표시(▼, ◆와 거리)가 그대로 나와서 지도의 적 표시와 헷갈림
- `WaveManager`의 적 표시 조건에 `!MapStrike.IsMapOpen`을 추가해 지도가 열려 있을 때는 숨김

- **요구사항**: 임시 디버그 표시(`OnGUI`)를 실제 게임 UI로 교체 (완성도 개선)
- **스크립트**: `GameHUD.cs` (신규), `Editor/HudLayoutTool.cs` (신규), `WaveManager`·`FireCannon`·`TankCamera`·`MapStrike` (임시 표시 끄기 스위치 추가)

### 화면 구성
| 위치 | 내용 |
|---|---|
| 왼쪽 위 | 웨이브 (`WAVE 2 / 5`), 남은 적 수 |
| 위 가운데 | 상태 안내 (웨이브 클리어, 승리·패배 등) |

| 가운데 | 일반 조준점 `+` / 정밀 조준 시 빨간 십자선 + 거리 |

   - HP바·장전바는 `Image Type = Filled`로 만들고 `fillAmount`(0~1)로 길이 표현
   - 정밀 조준 여부(`TankCamera.IsPrecision`)에 따라 일반 조준점과 조준경 화면을 `SetActive`로 전환
2. **자동 배치 도구** (`Tools > TankAttack > Layout Game HUD`): Canvas 아래 HUD 오브젝트를 이름으로 찾아 위치·크기·글자 크기·색을 일괄 설정

   - 흰 눈 배경 위에서도 글자가 보이도록 검은 `Outline` 추가
   - 기존 임시 표시는 Inspector 스위치로 끄고, 적 위치 표시와 지도 화면은 유지

```csharp
// HP: 이벤트로 바뀔 때만 갱신
health.OnHpChanged += UpdateHp;
void UpdateHp(float curr, float max)
{
    hpFill.fillAmount = curr / max;
    hpText.text = $"HP  {curr:0} / {max:0}";
}

// 장전 바: 장전이 끝나면 가득 참
reloadFill.fillAmount = 1.0f - fire.ReloadRemaining / fire.Current.reloadTime;
```

- **직접**: HUD에 표시할 정보 구성 결정, Canvas와 UI 오브젝트(텍스트, HP바, 조준점 등) 생성, **자동 배치 결과를 보고 위치·크기·색을 직접 다듬어 최종 디자인 완성**, 테스트

## 13. 아군 AI 탱크

- **요구사항**: 추가 기능 (기획 단계에서 직접 낸 아이디어, 필수 요구사항을 먼저 끝낸 뒤 진행)

- **프리팹**: `Resources/Allies/Ally_Tank` (파란색, HP 180)
- **상태**: ✅ 완료

### 구현 방법
1. **진영(Team) 도입**: `TankHealth`에 `Team { Player, Enemy }` 추가. 플레이어와 아군은 Player, 적은 Enemy
2. **포탄 오인 사격 판정 일반화**: 예전에는 "적끼리만" 데미지가 없었는데, 이제 **쏜 쪽과 맞은 쪽의 진영이 같으면** 데미지 없음 → 플레이어와 아군끼리도 오인 사격 없음
3. **AI 목표 선택 일반화**: 기존 적 AI는 플레이어만 쫓았는데, 1초마다 **가장 가까운 상대 진영 탱크**를 목표로 다시 고르도록 변경
   - 같은 `EnemyTank` 코드를 `isAlly`만 바꿔서 아군에도 재사용
   - 적은 플레이어와 아군 중 가까운 쪽을 공격
   - 아군은 싸울 적이 없으면 플레이어 근처(30m)를 따라다님
4. **소환·증원 (`WaveManager`)**: 시작할 때 플레이어 양옆 뒤쪽에 아군 2대, 웨이브를 클리어할 때마다 파괴된 아군을 다시 채움
5. 아군이 죽어도 남은 적 수에는 영향 없음 (`OnEnemyDied`는 적만 발생)
6. 화면에 파란 "아군" 표시, 전술 지도에 파란 ● 표시

```csharp
// 가장 가까운 상대 진영 탱크를 목표로
foreach (TankHealth h in FindObjectsByType<TankHealth>(FindObjectsSortMode.None))
{
    if (h.IsDead || h.team == health.team) continue;   // 죽었거나 같은 편이면 제외
    float d = (h.transform.position - tr.position).sqrMagnitude;
    if (d < best) { best = d; target = h.transform; }
}
```

### 직접 / AI 구분
- **직접**: 아군 AI 아이디어 제시, 마감 일정을 보고 필수 요구사항을 먼저 끝낸 뒤 진행하기로 판단, 테스트
- **AI 도움**: 진영 구조 설계, 기존 적 AI를 아군에도 쓸 수 있게 일반화하는 코드 작성

## 16. 물리 기반 이동 · 장애물 회피

- **계기 (직접 발견)**: 구조물을 추가한 뒤 테스트하다가 **전차가 건물을 뚫고 지나가고, 뚫는 도중 하늘로 튀어 오르는 버그**를 발견. 그리고 "AI 전차가 건물을 알아서 피해 가는가?"를 확인
- **스크립트**: `TankMove.cs`(수업 코드 수정), `EnemyTank.cs`, `WaveManager.cs`, `Editor/WinterBaseBuilder.cs`(상자 콜라이더 추가 메뉴)
- **상태**: ✅ 완료 (건물 충돌, 튕김 없음, AI 회피 확인)

### 원인
- 수업 코드의 `transform.Translate()`는 물리 엔진을 거치지 않고 **위치를 순간이동**시키는 방식이라 충돌 검사를 건너뜀 → 건물 안으로 들어감
- 그 뒤 물리 엔진이 "겹쳤다"고 판단해 겹친 만큼 강하게 밀어냄 → **하늘로 튀어 오름**
- 적 AI도 같은 방식이라 건물을 뚫고 지나가서 장애물을 피할 필요가 없었을 뿐, **실제로는 길 찾기나 회피 기능이 없었음**

### 해결
1. **이동 방식 변경**: 입력은 `Update`에서 읽고, 실제 이동은 `FixedUpdate`에서 **`Rigidbody.linearVelocity`(속도)와 `MoveRotation`**으로 처리 → 물리 엔진이 충돌을 처리해 건물에 막힘
   - 위아래 속도는 그대로 두어 중력은 물리 엔진에 맡김
   - `maxDepenetrationVelocity = 2`: 혹시 겹치더라도 밀어내는 속도에 상한을 둬서 튀어 오르지 않게
   - `Interpolate`로 물리 이동을 화면에서 부드럽게
2. **AI 장애물 회피**: 앞쪽 25m로 구(`SphereCastAll`)를 쏴서 건물이 감지되면 ±30° → ±60° → ±90°로 넓혀 가며 트인 방향으로 돌아감 (지형과 다른 탱크는 장애물로 보지 않음)
3. **끼임 탈출**: 움직이려는데 2초 넘게 1m도 못 움직이면 1.5초 동안 후진하면서 좌우 한쪽으로 방향을 틈
4. **소환 위치 검사**: 적·아군을 소환할 때 반경 12m 안에 건물이 있으면 다른 자리를 찾음 (`Physics.OverlapSphere`)
5. **일부 구조물이 여전히 뚫림 (직접 발견)** → 원인과 해결
   - 팩의 구조물은 모두 모델 모양 그대로의 **얇은 면(Mesh Collider)**이라 속이 비어 있고, 격납고 앞이나 감시탑 다리 사이처럼 빈 곳도 있음
   - 적 탱크는 고속 충돌 검사(CCD)가 꺼져 있었음
   - 해결: `Tools > TankAttack > Add Solid Colliders to Winter Base`로 구조물마다 모델 크기에 맞는 **꽉 찬 Box Collider**를 추가 (건물 기준 로컬 좌표로 모든 메쉬를 감싸는 상자를 계산해서 회전한 건물에도 딱 맞음), 적 탱크에도 `ContinuousDynamic` 충돌 검사 적용
   - 자동으로 만든 상자가 모델과 살짝 안 맞는 곳은 **직접 크기와 위치를 수작업으로 조정**
- 길 찾기(NavMesh)도 검토했으나, 패키지 설치·맵 굽기·AI 재작성이 필요해 마감 일정상 간단한 회피 방식을 선택

```csharp
// TankMove: 순간이동(Translate) 대신 물리 속도로 이동
void FixedUpdate()
{
    rbody.MoveRotation(rbody.rotation * Quaternion.Euler(0.0f, rotSpeed * h * Time.fixedDeltaTime, 0.0f));
    Vector3 velocity = tr.forward * v * moveSpeed;
    velocity.y = rbody.linearVelocity.y;   // 중력은 물리 엔진에 맡김
    rbody.linearVelocity = velocity;
}
```

### 직접 / AI 구분
- **직접**: 건물 관통·튕김 버그 발견, AI 회피 여부 확인 질문, 일부 구조물이 여전히 뚫리는 문제 발견, 상자 콜라이더가 안 맞는 곳 수작업 조정, 테스트
- **AI 도움**: 원인 분석(Translate는 물리 충돌을 건너뜀), 이동 방식 변경, 회피·끼임 탈출·소환 검사 코드 작성

## 17. 일시정지 메뉴

- **계기**: 빌드 전에 "마무리할 게 더 없는지" 점검 → 전투 중에 게임을 나가거나 처음으로 돌아갈 방법이 없다는 점 확인 (Esc는 커서만 풀어 줌, 빌드는 전체 화면이라 교수님이 채점하다 나가기 어려움)
- **스크립트**: `PauseMenu.cs`, `PauseState.cs` (신규), `TankCamera.cs`, `FireCannon.cs`, `MapStrike.cs`, `SceneLoader.cs` (수정), `Editor/HudLayoutTool.cs` (Add Pause Menu 메뉴)
- **상태**: 🔧 테스트 중

### 동작
- 전투 중 **Esc** → 화면이 어두워지며 **일시정지** (계속하기 / 처음으로 / 게임 종료), Esc를 다시 누르면 계속
- 지도가 열려 있을 때의 Esc는 지도 닫기용이라 일시정지하지 않음, 승패가 정해진 뒤에는 열리지 않음
- Intro 조작법 안내도 `Esc : 커서 풀기` → `Esc : 일시정지 메뉴`로 변경

### 구현 방법
1. **`Time.timeScale = 0`**: 게임 시간을 멈춤. `Update`는 계속 실행되지만 `Time.deltaTime`이 0이 되어 이동·재장전·쿨타임·코루틴 대기가 모두 멈춤
2. **`PauseState`(static)**: 카메라, 발사, 지도 포격이 일시정지 여부를 확인하도록 공유
   - 일시정지 중에는 카메라가 커서를 다시 잠그지 않고, 지도가 열리지 않음
   - "계속하기" 버튼을 누른 그 프레임의 클릭이 포탄 발사로 이어지지 않도록 바뀐 프레임 번호를 기록해서 무시
3. 일시정지 상태로 다른 씬으로 가면 시간이 멈춘 채 시작되는 문제를 막기 위해, 씬을 옮길 때와 씬이 시작될 때 `Time.timeScale = 1`로 되돌림

```csharp
public void Pause()
{
    PauseState.IsPaused = true;
    Time.timeScale = 0.0f;           // 게임 시간 정지
    panel.SetActive(true);
    tankCam.SetCursorLock(false);    // 버튼을 누를 수 있게 커서 보이기
}
```

### 직접 / AI 구분
- **직접**: 빌드 전 마무리 점검 요청, 일시정지 메뉴 추가 결정, 테스트
- **AI 도움**: 전투 중 나갈 방법이 없다는 점 제안, `PauseMenu`·`PauseState` 코드, 기존 카메라·발사·지도 코드와 충돌하지 않게 연결, 일시정지 화면 생성 도구

- **라이선스**: Creative Commons: By Attribution 4.0 → 무료 사용 가능, **출처 표기 필수**
- **상태**: 🔧 진행 중

### 작업 내용
- **곡 선정 (직접)**: 에셋 스토어 외의 무료 음원 사이트에서 설원 전선 분위기에 맞는 전투 음악을 직접 고름 (현악·호른·타악기 중심, 6분 16초로 길어 반복감이 적음)
- **라이선스 확인**: CC BY 4.0이라 출처 표기 문구를 PPT·README 크레딧과 **게임 Intro 화면**에 넣음
  - Intro 왼쪽 아래에 작은 글씨로 표기 (`Tools > TankAttack > Add Music Credit`)
- **Unity 설정**: 긴 곡이라 빌드 용량과 메모리를 줄이도록 Load Type은 Streaming, 압축은 Vorbis
- **재생**: 전투 씬에 Audio Source (Play On Awake, Loop, 2D, 낮은 볼륨으로 포탄 소리가 묻히지 않게)
